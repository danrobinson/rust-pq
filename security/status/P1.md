## `skPrfQueries` (the architect's unchecked estimate)

Checked. The estimate is a **valid upper bound but not the exact count**; nothing is false and no
frozen statement has to change.

- true count of provider reads: key generation `2^hp * len` (one top XMSS tree); each signature
  `k * 2^a` (per FORS tree: the opened secret + the `2^a - 1` sibling leaves of the authentication
  path) plus, per hypertree layer, `(2^hp - 1) * len` (authentication path: the signing leaf is
  not regenerated) `+ len` (WOTS+ signature) `= 2^hp * len`. Total
  `2^hp * len + qs * (k * 2^a + d * 2^hp * len)`.
- `skPrfQueries vp qs = 2^hp * len + qs * (k * 2^a + d * ((2^hp + 1) * len))` overcounts by
  `qs * d * len`.
- Optional tightening (cosmetic; `skPrfQueries` is defined in `PRFHop.lean`, which P1 owns, and
  is mentioned only in `REDUCTION_STATUS.md` §3/§7, not in any frozen Lean file):
  `skPrfQueries`: `vp.params.d * ((2 ^ vp.params.hp + 1) * vp.params.len)` →
  `vp.params.d * (2 ^ vp.params.hp * vp.params.len)`; then `bPrf_queryBound` is
  `bPrf_queryBound_exact` verbatim (`unfold skPrfQueries signReads`). Left as is so the skeleton
  `.olean` statement stays valid. The bound counts queries, not distinct points: `bPrf` re-reads
  the same secrets across signatures (the count is tight for the program, not for the set of
  addresses).

## How it is proved

- One program identity serves both worlds (`rest_sim`): for any `h : PkSeed × Adrs → Y`,
  `simulateQ (Tables.fnImpl h) (bRest A pkSeed)` is "sample `SK.prf`, run
  `alg.runWithSigningOracle`, check freshness and validity" for any `SignatureAlg` `alg` whose
  root and signer are the `h`-interpretations of the provider programs. Ingredients:
  `keygen_sim`/`sign_sim` (two applications of VCVio's `*_natural`: along
  `simulateQ' (fnImpl h)` and along `QueryHom.ofSimulateQ`), and `run_eq` (P2's `realRun_eq`
  generalised: `QueryImpl.map_run_withLogging_inputs_eq_run_appendInputLog`).
- Real world: `prfRealQueryImpl (skPrf) k = fnImpl (fun d => PRF d.1 k d.2)` by `rfl`;
  `alg := internalAlg`, VCVio `rootWithSecretM_eq_rootM` and
  `signInternalWithSecretRandomizerM_eq_signInternalWithRandomizerM`; one
  `evalDist_bind_bind_swap` (key before `PK.seed`).
- Ideal world: `Reduction.evalDist_prfIdeal_eq_sampleTable` (P0) with `pre := pkSeedDist`,
  `pk := id`, `rest := bRest A`; then `rest_sim` at `alg := tableAlg`, `h := secretOf tbl ∘ snd`
  (root and signer hypotheses are `rfl`). No reordering needed. The side condition
  (`queriesIn_bRest`) is `SecretTraces.*_pred_of_ledger` at `Q := QueriesIn S` plus
  `canonical_of_secretChild` (every secret child of a ledger address is canonical, from
  `mem_secretChildren_of_inl_mem_childAdrs` and `addressFacts_*`), and
  `AllQueriesSatisfy.simulateQ_run` for the harness.
- Query bound: inside `bPrf` the hash callbacks are `pure`, so the provider programs have a
  *total* query bound; VCVio `isTotalQueryBound_merkleRootM` / `_intrinsicAuthPathM` with node
  budget 0 and leaf budget `len` (XMSS) or `1` (FORS), the `*_pred` lemmas of
  `AddressDiscipline` at `Q := IsTotalQueryBound · 0` for the recovery programs, then
  `IsTotalQueryBound.isQueryBoundP` and `IsQueryBoundP.simulateQ_run_of_step_le` (cost
  `signReads vp` per signing query).
