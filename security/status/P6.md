## Statement change inside the owned file (lead: please note)

`wotsAnswer_wins`, old hypotheses
`hsim : ∀ m R, signFromHist tbl hist pk m R = idealSign vp prims tbl m pk R` and
`hhist : ∀ e ∈ hist, e.2.2.2 = wotsPkFromSigTops prims e.2.2.1 e.2.1 pk.pkSeed e.1`

`hvalid` is kept but unused. No frozen file is affected; nothing outside the file uses the lemma.

## Revision of the adversary `bWots` (same name, same type; `Final.lean`, `WotsUD`, `WotsFinal`
use it opaquely)

Behaviour is the paper's (evaluate the hypertree with every WOTS+ instance signed once by the
game, answer signing queries from the recorded signatures, single run of `A`); the draft's
"identity-hash device" was replaced by explicit constructions, which is what made the proof go
through:
- `msgAt tbl (l+1) tree leaf`: explicit `PerfectMerkleTree.merkleRootM` over leaves
  `T_len(chain ends from topsAt)` with all hashes sent to the collection oracle (was: honest
  `xmssRootWithSecret` run with identity chain hash and chain ends as "secrets"). `instOf` removed.
- `chooseBody tbl` (new, phase 1 after the table draw): first calls `topsAt` for every
  `pos ∈ allWotsInstances vp` (memoised, so each instance is still signed exactly once), then
  `msgAt tbl d 0 0`. The explicit loop makes "every instance has an entry" immediate.
- `signFromHist`: FORS part unchanged; hypertree layer `j` is now ⟨recorded WOTS+ signature of
  the path instance, `intrinsicAuthPathM` over leaves `T_len(recorded chain ends)`⟩ (was: honest
  `signWithSecret` with a modified chain hash). `histEntry` (lookup with dummy default) is new.
- `wotsAnswer`: unchanged.
No `Classical.choose`, no search, no second run of `A`.

## The simulation-coupling statements (previously missing)

- `chooseBody_run`: against the game oracles whose start values are read from the table
  (`tblOracles tbl pk`), phase 1 is deterministic: returns `idealRoot vp prims tbl pk`, mirrored
  history = game history, and it is `HistGood`. (No refusal: collection keys are never reserved —
  `keyInj` + `bounds` + address types; no instance is signed twice — memoisation.)
- `signFromHist_eq_idealSign`: on a good history the phase-2 signer *is* `idealSign` — so the
  forger's view is that of `G2`.
- `wotsAnswer_wins`: good history + class `wots` ⇒ `WotsGame.win`.
- `wotsCell_inj`, `chooseBody_congr`, `signFromHist_congr`: WOTS start-value cells are distinct
  table cells and `bWots` reads its own table only outside them.
- `fresh_eq_table`: via `evalDist_sampleTable_bind_freshImpl_block` (P0; works as advertised),
  the game's fresh per-instance vectors + the adversary's table = one uniform table
  (`q_queriesIn`, `q_noRepeat`, `q_push` supply `hoa`, `hnr` and the two `simulateQ` views).
- `table_step`, `hyb_bWots_eq`, then `stepWotsEmbed` by `prTrue_bind_mono`/`prTrue_bind_congr`.

All three fields of `Structural` are not needed: `byteLaws` is unused here; `keyInj` and `bounds`
are used.
