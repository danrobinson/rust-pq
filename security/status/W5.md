## The adversary (`namespace Reduction`)

Observation: `TcrSplit.restrict` already carries the list `L` of `bTcrS`'s accepted targets in its
state (`(tbl, L)`, used only for the index translation), and in the game `L = honestCalls tbl pk`
(`bTcrArS_choose_run`). The old phase 2 ignored it and recomputed `honestCalls tbl pk`.

```lean
def chkM (pk) (targets) (c) : Option (ℕ × List prims.Y) :=       -- lookup BY TWEAK, ≤ 2 Thash
  match targets[targets.findIdx fun t => decide (t.1 = c.1)]? with
  | none => none
  | some t => if c.2 ≠ t.2 ∧ prims.Thash pk c.1 c.2 = prims.Thash pk t.1 t.2
              then some (targets.findIdx (fun t => decide (t.1 = c.1)), c.2) else none
def findCollisionM (pk) (targets calls) := calls.findSome? (chkM pk targets)
def classOut prims n L jm : ℕ × {xs // xs.length = n}             -- output translation of TcrSplit.restrict (copied)
noncomputable def memoForge n A (s : SecretTable vp prims × List (prims.AdrsKey × List prims.Y)) pkSeed := do
  let pk := idealPk vp prims s.1 pkSeed
  let z ← g2Run A s.1 pk
  return classOut prims n s.2 ((findCollisionM pkSeed s.2 (verifyCalls pk z.1.1 z.1.2)).getD (0, []))
noncomputable def bTcrArM (n) (A : Forger …) : SM_DT_TCR_Adversary (thashArityProblemT vp prims pkSeedDist n) where
  State  := SecretTable vp prims × List (prims.AdrsKey × List prims.Y)
  choose := (simulateQ (TcrSplit.route (thashList vp prims pkSeedDist) (·.length = n) (tcrTargets vp)) (Lazy.bTcrS A).choose).run []
  forge  := memoForge n A
```

* Phase 1 is literally that of `bTcrArS n A` (= `bTcrArST n A`): `bTcrArM_choose : (bTcrArM n A).choose = (bTcrArS n A).choose := rfl`.
* The reduction's memory across the reveal: `tbl` and `L` (`tcrTargets vp` pairs `(tweak, input)`,
  distinct tweaks: `bTcrArM_state`).
* **What is and is not looked up (deviation from the task text, stated plainly).** Only the
  structure recomputation of the collision search is replaced by lookup in `L`. The stored table
  holds `(tweak, input)` pairs, NOT the phase-1 answers; therefore (i) `PK.root` is recomputed
  (one top tree, `keygenHashes`), (ii) signatures are simulated by local hashing from `tbl`
  (`≤ signHashes` per signature — poly in `qs`, the same kind of cost as the FORS-leaf
  adversaries), (iii) the collision test evaluates `Thash` at the one stored entry with the tweak
  of the verification call (≤ 1 per call). The bound has no `tcrTargets` term. Only the tight
  problem is covered (`bTcrArM_advantage_eq_loose` relates the advantage to `bTcrArS n A`); no
  loose-cap twin was defined.

### Would lookup of the phase-1 ANSWERS remove the per-signature hashing? (analysis, not formal)

Yes for `Thash`, no for `H_msg`. Per signature the simulation (`idealSign tbl`) evaluates:
`H_msg(R, PK.seed, PK.root, M)` once — not a `Thash` call, depends on the forger's message, never
obtained in phase 1 (R is a lazy uniform value in `G2`, no `PRF_msg`); FORS: `k` whole trees
(`F` leaves, `H` nodes) + `T_k`; hypertree: per layer a whole XMSS tree (WOTS chains `F`, `T_len`,
`H` nodes) + the recovery. Every one of these `Thash` calls is a call of `structureVia`
(the key structure contains all FORS trees and all XMSS trees), and EVERY class adversary got
its value in phase 1: `TcrSplit.routeStep` sends an accepted call to the challenge oracle if its
arity is `n` and to the collection oracle otherwise, and both return the hash value. FORS/WOTS
secrets are table reads. So an answer-storing variant would need only `1` `H_msg` per signature
and the verification of the forgery. Not done because the formal count would not improve
without two new proofs: a wrapper recording answers with its own `choose_coupling`, and
"every hash query of `openSign` is in `honestCalls`" (existing `sub_*`/`verifyCalls_idealSign_subset`
cover only the verification calls of the reference signature, not the tree recomputations).

## (1) Equal advantage — closed, equality of experiments

## (3) Phase 2: own hash evaluations (`namespace Reduction.Resources2`, W3's counting model)

```lean

```
(`tI tbl := Lazy.tblImpl (PublicHash.impl prims) tbl`; `hA : ∀ pk, IsQueryBoundP (A.main pk) (·.isRight = true) qs`.)

**Counted formally** (hash queries of `memoForgeOpen`, which the interpretation theorem proves
to be the adversary's phase-2 program): `PK.root` (`keygenHashes`), all signing (`qs·signHashes`),
the `H_msg` of the forgery (1), every `Thash` of the verification of the forgery (`≤ verifyHashes`),
every `Thash` of the collision test (`≤ 1` more per verification call). W3's "argued tail"
(`verifyCalls`/`findCollision`, `≤ 11784`) is now formal and smaller (`7856 + 1`). The pure code
of `memoForgeOpen`/`collO`/`verifyFree` contains no `prims.Thash/Hmsg` (inspection).
**Not counted / argued:** the forger's own computation (black box; its queries are counted, its
hashing is its own); list work — `findIdx` in the `tcrTargets`-entry list `L` per verification
call (≤ 3928 lookups; a keyed table in practice), `classIdx` (one filter-count over a prefix of
`L`), `G2` log; the general caveat of W3 (the model certifies the open program written down; no
lower bounds). The bound is an upper bound; with answer lookup it would drop to
`≈ qs + 1 + verifyHashes` (analysis above).

## Other structure-walking adversaries (re-examined against W3's table and the sources)

Nothing else recomputes the structure after the seed is revealed:
* `toDspr/toTcr (Lazy.bOpenPreS A)`: phase 2 `≤ 269839 + qs·1950028` hash queries, formal and
  complete (`findOpenFull_hashes`); targets' images are stored in the state (`ys`).
* `rUd/rPre/rTcr(T) pkSeedDist (Lazy.bWotsS A)`: `≤ qs·121857 + {525, 560, 16800}` formal; the pure
  tail `wotsAnswer` (`Reduction/WotsEmbed.lean:132`: one `signFromHist`, FORS pk and `layerMsg` of
  the forgery, a `findIdx` in the history) is per-forgery work, argued `≤ 129714`; no walk over
  `structureVia`/`honestCalls`.
* `bPrfC`, `bPrfWC`, `Lazy.bPrfMsgL/WL`, `Lazy.bItsrL` are single-phase (no seed reveal), lazy,
  `≤ keygenHashes + qs·signHashes` (+ one verification).

adversaries and the unsplit `bTcrS`).
