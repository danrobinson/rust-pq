# Docstrings that overclaim efficiency / explicitness, with corrections

(Note added by the W6 documentation sweep) These corrections have been applied to the sources; the `file:line` references in the table are to the phase-1 sources and no longer match. Later finding (`status/W3.md`): `bTcrS A` and the four `bTcrArS n A` also recompute the whole key structure after the seed reveal (`≈ 2^79.81` own hash evaluations at 128s).

Scope: existing files under `Reduction/` (not edited), plus `status/FINAL.md`.  Numbers quoted are
proved in `Reduction/Resources.lean` (`Reduction.Resources.*`).  "Explicit" in the existing text
means only "choice-free definition"; it must not be read as "feasible".  Wherever the lazy/sparse
variants (`Reduction/Lazy/*`) land, "no lazy variant is proved" becomes false and must be replaced
by a pointer to them; the corrected texts below are written so that they stay true either way.
