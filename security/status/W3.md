## Method

* **Phase 1 (seed hidden).** Statements about the run of the adversary's phase-1 program against
  the oracles of its own game from the initial state, for every seed `pk`: either an equation
  exhibiting the run in closed form (fresh samples appear as `Tables.sampleList prims.Y n` /
  `ForsTight.sampleT ($ᵗ prims.Y) keys`), or `∀ z ∈ support (run), <count of z.2>` where `z.2` is
  the game's own record of accepted target/challenge queries and collection queries.
* **Phase 2 (seed revealed).** Hashing is modelled as in `Reduction/Lazy`: an *open program*
  `P : OracleComp (Lazy.OSpec prims gspec) α` (`unifSpec + (gspec + ((SecIdx →ₒ Y) + publicHashSpec))`)
  in which every `Thash`/`Hmsg` evaluation is a query of kind `.hash`; a theorem
  `simulateQ (Lazy.tblImpl (PublicHash.impl prims) tbl) P = <the adversary's phase-2 program>`
  (hash queries evaluated by `prims`, secret-oracle queries read from the adversary's table
  `tbl`, which is part of its state); and `IsQueryBoundP P (fun t => Lazy.kind t = .hash) N`.
  Where the phase-2 program is a `ProbComp`, the equation is stated after `liftM` into
  `OracleComp (unifSpec + gspec)` for an arbitrary `gspec`.
* **Elaboration.** Unfolded `∀ z ∈ support …, z.2.1.length …` statements at `rUd/rPre/rTcr
  pkSeedDist (Lazy.bWotsS A)` and at `bTcrArS n A` time out in `whnf` (200000 heartbeats) —
  tried: direct statement with term proof, `▸`, `Eq.mp (congrArg …)`.  They are therefore stated
  through predicates generic in the adversary (`UdChallengesLe`, `PreChallengesLe`,
  `WTcrTargetsLe`, `TcrPhase1Counts`; `P (concrete term)` elaborates without unfolding; proved
  once generically, then `exact generic _`).  Unfold the predicate to read the statement.  All
  other statements are at the concrete terms literally.

## Findings that matter for the ideal-model analysis

1. **`bTcrArS n A` (all four class adversaries) recompute the whole key structure in phase 2**:
   `(Lazy.bTcrS A).forge tbl pkSeed` evaluates `honestCalls tbl pkSeed` because the state carried
   across the seed reveal is the table only (answers of the phase-1 queries are discarded).
   That is exactly `tcrTargets vp` (`≈ 2^79.81` at 128s) local `Thash` evaluations at the revealed
   seed, independent of `qs` (`tcr_structure_exact`; upper bound `tcrForgeOpen_hashes`).  The
   expectation "phase 2 is poly(`qs`)" is FALSE for these four terms as defined.  It could be
   made true only by changing the adversary (store the phase-1 answers in the state), which this
   package was not allowed to do.
2. For the FORS-leaf adversaries and the three chain adversaries the expectation holds:
   phase 2 is `≤ 269839 + qs·1950028` resp. `≤ qs·121857 + {525, 560, 16800}` (+ `wotsAnswer`)
   at 128s.  The chain adversaries do no chain hashing in phase 2 for signing (chain ends are
   read from the recorded history).
3. **Phase 1, own hashing = 0**: checked by inspection, NOT a theorem.  The phase-1 programs
   (`bOpenPreWith.pick`, VCVio `toDSPR/toTCR` choose, `Lazy.bTcrWith.choose` = `structureVia` over
   the target oracle, `TcrSplit.route`, `chooseBody`/`msgAt`/`topsAt`, `WotsGame.simChoose`,
   `udStart`/`preStart`/`tcrStart`, `*ChainHash`, `*Coll`) contain no occurrence of
   `prims.Thash/F/H/Tl/PRF/Hmsg/PRFmsg`; every hash value comes from a target/challenge or
   collection query (the proved run equations show the game answering them).  A formal "zero"
   is not expressible: an open program with zero hash queries always exists trivially, so the
   hash-oracle model only certifies the programs one writes down.  The same caveat applies to
   every phase-2 count: the open programs were written so that no `prims.*` evaluation remains
   in pure code except the listed tails; the interpretation theorems prove they compute the
   adversary's program, the bounds count their hash queries.
4. Not hashing but structure-size anyway (not counted anywhere): list work in phase 2 —
   `leafTarget`/`leafImage` (`idxOf`/`getD` in lists of `2^h·k·2^a` entries, FORS-leaf
   adversaries), `histEntry`/`findIdx` over the `#inst`-entry history (chain adversaries),
   `findIdx` over `tcrTargets` targets and `classIdx` (class adversaries); and the size of the
   state carried across the reveal.

## Not done, and why

* Collection-query counts and own-sample counts of `rUd/rPre/rTcr` (and of `bWotsS A`'s
  collection queries): counting arguments only (table above).  A proof needs a query-count
  invariant through `WotsGame.simChoose`/`chooseBody` (memoised recursion `msgAt`), and a
  draw-explicit version of `udStart/preStart/tcrStart`; not attempted for lack of time.
* The pure tails `verifyCalls`/`findCollision` (class adversaries) and `wotsAnswer` (chain
  adversaries) are not expressed as hash queries; argued bounds in the table.
* No lower bounds on hash evaluations can be stated (no cost model); "exactly `tcrTargets`"
  is the length of the evaluation log `honestCalls`, and the upper bounds are `IsQueryBoundP`.
* Hash counts for `bPrfC`/`bPrfWC` are not modelled (pre-existing gap; they are single-phase PRF
  distinguishers).
