# RustCrypto SLH SHA-2 suite

Run `scripts/check-peer-sha2-suite.sh` in the repository with the pinned Rust and Lean tools and the project’s Lean dependencies installed. Cargo supplies the immutable crate archives from the benchmark lockfile. The check verifies their SHA-256 checksums, translates the suite again, compares both generated Lean files, builds the proofs and audits the headline axioms.

`suite_is_fips` compares six outputs simultaneously for SHA2-128s/f, SHA2-192s/f and SHA2-256s/f. Its inputs include arbitrary hash-tree rows, arbitrary nested message fragments and an HMAC key of the parameter set’s length. It covers both cached hashers, 22-byte ADRSc, hash input order, left truncation, inner/outer HMAC, MGF1 big-endian counters and the partial final MGF block. SHA2-128f consumes two MGF digests. The other five variants consume one. `mgf_counter_fits` proves that every checked conversion succeeds.

`Suite.lean` is generated from the locked `slh-dsa 0.2.0-rc.5` method bodies. The extractor recognizes a restricted grammar of Rust operations and preserves the order and source of each update. It checks the concrete digest, HMAC, SHA and block-buffer method bodies underlying its operations against their supported forms. `Initial.lean` contains the actual initialization vectors from `sha2 0.11.1`. `Buffer.lean` proves that the three paths of the eager update preserve the byte stream, emit a whole number of blocks and leave fewer than a block pending. `absorb_buffer` applies this result across arbitrary fragmentation.

`Digest.lean` runs the extracted RustCrypto Linux AArch64 hardware compressor on every padded block and serializes its words big-endian. The kernel checks that this digest equals the independent FIPS SHA transcription for every byte list. The concrete machine length calculation uses the FIPS 180-4 domain of fewer than 2^61 input bytes to SHA-256 and 2^125 input bytes to SHA-512, including any prefixes. `machine_length` proves the bit counters fit on that domain. The existing `scripts/check-rustcrypto-arm-code.sh` independently regenerates and validates the emitted compressor instructions.

The binding from upstream Rust source to byte streams trusts the restricted translator and the interpretation of Rust’s default arrays, byte slice copying, array views, iterators, cloning and big-endian serialization. Its memory model treats valid, initialized Rust slices as byte sequences. The address argument starts at the raw 32-byte address and the message starts at the ordered fragments supplied to the hash suite. Caller-side construction of those values is outside this theorem. The hardware digest instantiation uses the existing Arm instruction semantics and release-code extraction. Independent x86 peer machine code, the compiler as a whole, side channels and cryptographic security are outside this result.
