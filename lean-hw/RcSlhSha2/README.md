# RustCrypto SLH SHA-2 suite

Run `scripts/check-peer-sha2-suite.sh` in the repository with the pinned Rust and Lean tools and the project’s Lean dependencies installed. Cargo supplies the immutable crate archives from the benchmark lockfile. The check verifies their SHA-256 checksums, translates the suite again, compares both generated Lean files, builds the proofs and audits the headline axioms. A negative control reverses the two Rust updates in H and requires the FIPS theorem to fail on all six sets.

`suite_is_fips` compares six outputs simultaneously for SHA2-128s/f, SHA2-192s/f and SHA2-256s/f. Its inputs include arbitrary hash-tree rows, arbitrary nested message fragments and an HMAC key of the parameter set’s length. It covers both cached hashers, 22-byte ADRSc, hash input order, left truncation, inner/outer HMAC, MGF1 big-endian counters and the partial final MGF block. SHA2-128f consumes two MGF digests. The other five variants consume one. `mgf_counter_fits` proves that every checked conversion succeeds.

`Suite.lean` is generated from the locked `slh-dsa 0.2.0-rc.5` method bodies. The extractor recognizes a restricted grammar of Rust operations and preserves the order and source of each update. It checks the concrete digest, HMAC, SHA and block-buffer method bodies underlying its operations against their supported forms. `Initial.lean` contains the actual initialization vectors from `sha2 0.11.1`. `Buffer.lean` proves that the three paths of the eager update preserve the byte stream, emit a whole number of blocks and leave fewer than a block pending. `absorb_buffer` applies this result across arbitrary fragmentation.

`Digest.lean` runs the extracted RustCrypto Linux AArch64 hardware compressor on every padded block and serializes its words big-endian. The kernel checks that this digest equals the independent FIPS SHA transcription for every byte list. The concrete machine length calculation uses the FIPS 180-4 domain of fewer than 2^61 input bytes to SHA-256 and 2^125 input bytes to SHA-512, including any prefixes. `machine_length` proves the bit counters fit on that domain. `suite_on_platform` additionally proves the unique digest behavior and all six suite results when SHA-256 and SHA-512 independently select an Arm Linux kernel, Arm Apple kernel, x86 SHA-NI/AVX2 kernel, or the portable software provider. For each input, any grouping of its padded blocks into valid Rust slices is permitted. Total-correctness postconditions cover every batch, including odd and even AVX2 sizes. `fragmented256` and `fragmented512` connect the actual cursor and compressed-block counts after arbitrary updates to final padding. Equal byte streams in fixed-size blocks determine the complete sequence uniquely. `singletonPartition` supplies a valid grouping for every input.

The underlying compressor gates are `scripts/check-rustcrypto-arm-code.sh`, `scripts/check-rustcrypto-shani.py`, `scripts/check-rustcrypto-avx2.py`, `scripts/check-rustcrypto-soft.sh` and `scripts/check-rustcrypto-soft512.sh`. They independently regenerate the released Arm instructions or the Aeneas translations of the x86 and software functions.

The binding from upstream Rust source to byte streams trusts the restricted translator and the interpretation of Rust’s default arrays, byte slice copying, array views, iterators, cloning and big-endian serialization. Its memory model treats valid, initialized Rust slices as byte sequences. The address argument starts at the raw 32-byte address and the message starts at the ordered fragments supplied to the hash suite. Caller-side construction of those values is outside this theorem. The hardware digest instantiation uses the existing Arm instruction semantics and release-code extraction. The x86 and software results use Aeneas translations of the Rust functions and the accompanying intrinsic and memory models. Routing describes a selected kernel on a machine with its required ISA. This theorem covers the four provider choices above. Other upstream backends such as wasm SIMD, RISC-V and LoongArch, the compiler as a whole, side channels and cryptographic security are outside this result.
