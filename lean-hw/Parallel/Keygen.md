# Hosted parallel key generation

For each FIPS parameter set, seeded public key generation returns the FIPS secret and public key bytes on AArch64 Linux, Apple Silicon and x86-64 Linux. The checked configuration uses the `parallel,platform-sha2` features. The public theorem accepts arbitrary seed bytes of length `3n` and secret/public output slices of lengths `4n` and `2n`.

The source gate extracts the 24 typed key-generation forwarders, both generic key writers, their `unwrap_or_else` closures and the live architecture-selected split calculation. Lean checks the scalar fallback, the successful parallel return, each buffer write and the two outputs. At tree height eight the x86 policy selects height-three subtrees and 32 jobs. Arm selects height-two subtrees and 64 jobs. [Split policy](KeygenPlan.lean) · [Public key writers](KeygenPublic.lean)

Each successful relaxed fetch owns one slot. The worker proof follows the actual number of participating invocations, including pool contention and unsuccessful spawns. For every normally completed schedule it establishes that each returned slot contains the node for its own index and that the counter fits in 32 bits. The public computation uses a maximal schedule witness. The schedule-independent theorem identifies the same root for every such witness. The secret and public keys are formed only after the join. [Fetched slots](KeygenTickets.lean) · [Worker and outer dispatch](KeygenDispatch.lean)

SHA-2 uses the checked Arm or x86 XMSS node implementation. For SHAKE, the gate lifts the dependencies of the actual uncached streaming subtree for every valid subtree position at heights one through nine, digest widths 16, 24 and 32, and SIMD widths three and eight. Lean checks child order, index offsets, height offsets and the returned root. For the width-eight fused leaf routines and packed parent calls, the link from compiled Rust to the per-lane primitive values uses symbolic execution. Its nine cases cover heights one, two and three at each digest width with arbitrary seeds and valid index. For heights three through nine, the verifier follows the optimized x86-64 subtree stack with arbitrary leaf and parent outputs. It checks all 21 digest-width and height combinations for both the original gather loops and the version used for Lean extraction, which copies the current row into a local variable before gathering children. These checks verify the arguments to each hash call, including child order and absolute address, and the bytes returned as the root. An intentionally swapped child fails this check. A separate compiled gate checks all packed parent cases with two, four and eight active lanes and arbitrary neighboring inputs. Target-specific proof replay substitutes the native sequential SHAKE sponge. [AArch64 and x86 SHA-2](KeygenSha2.lean) · [SHAKE geometry](KeygenTree.lean) · [SHAKE native replay](KeygenNativeHashes.lean) · [Compiled primitive gate](../../scripts/parallel-proof/subtree.py)

On Apple Silicon and x86-64 Linux the six SHAKE key-generation and seeded round-trip theorems instantiate the feature-dispatched Rust XMSS node. At height zero it generates one WOTS public key. The optimized branch uses the extracted two-, four- or eight-key leaf routines for heights one through nine. The x86 feature-off branch uses the recursive scalar implementation. [Subtree and leaf composition](../Buffered/AllNodes.lean) · [Host key-generation theorems](../Shakebatch/WidthEightGeneratedKeys.lean) · [Public API coverage](../Shakebatch/WidthEightCoverage.lean)

Run `python3 scripts/check-parallel-keygen.py` for the source and Lean gate, and `uv run scripts/parallel-proof/subtree.py` and `uv run scripts/parallel-proof/buffered_tree.py` for the compiled symbolic gates. These checks share the repository's Aeneas, compiler, intrinsic, instruction and pool-runtime trust boundaries. The primitive gate executes the optimized x86-64 projection of the shared width-eight Rust code.
