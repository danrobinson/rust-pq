# Linux Arm SHAKE signing worker

For each of the six SHAKE parameter sets, the checked Linux Arm worker projection returns a complete FIPS 205 signature when at least two threads are available. The generation, signing and verification composition returns `ok true` for arbitrary correctly sized seeds and keys, messages, valid contexts, signing randomness and key-generation pool outcomes. Lean separately proves that the enabled signer returns `some signature`. [Round trip and successful branch](SignJoinRoundTrip.lean)

The source check uses two representations of the same pool join.

- Charon and Aeneas extract the production availability guard and the complete post-join code from a scratch copy of the crate. The source projection replaces the work between the guard and the join by one function returning the three live cell tables. The final code reads both aggregate cells and each WOTS cell, checks their presence, and copies the randomizer, the FORS bytes and the interleaved WOTS signatures and authentication nodes. Lean checks every index, byte, allocation-size bound and copy. The physical-cell contract specifies the contents of the FORS vector, each XMSS authentication node and each WOTS output. [Extraction gate](../../scripts/check-parallel-sign-join.py) · [Copy loops](SignJoinRows.lean) · [Worker theorem](SignJoin.lean)
- The compiled Rust replay executes the production scheduler and records all three physical tables before the copy. The replay uses symbolic digest, key and address inputs. It interns the primitive call name and arguments, including every input byte, and compares every byte of every published row to an independently constructed reference call. The comparisons run at SIMD width three with the scalar and SIMD policies and one and four participating worker invocations. All four positive cases must produce the same row identities. Lean checks those identities and interprets each primitive result by its FIPS value. The six source-supported shapes use 182–350 FORS blocks, 63–68 authentication nodes and 7–22 WOTS signatures. [Physical-cell observations](../../scripts/parallel-proof/post-join-rows.rs) · [Row identities](SignJoinTable.lean) · [FIPS interpretation](SignJoinInterpreter.lean)

The source projection, Rust symbolic replay and their primitive-call encoding connect the native worker closure to the Lean interpretation. Direct extraction of the unmodified closure encounters an Aeneas limitation when joining shared region loans containing borrows in the XMSS worker. The kernel theorem covers the projected computation. The separate scheduler and pool proofs cover ticket ownership and publication ordering under their respective execution models. Native compiler, standard-library synchronization and actual memory execution remain part of the trust boundary. [Scheduling](SigningSchedules.lean) · [Publication](SigningPublication.lean)
