# Proof coverage of the persistent worker implementation

| Component | Checked property | Implementation boundary |
|---|---|---|
| Cached XMSS construction and signing | Lean proves that the local WOTS leaf and hash-parent equations imply the FIPS value of every reachable node. For any valid leaf, the extracted authentication-path loop then appends exactly the bytes required by XMSS signing, given the WOTS signature, tree size and output room. | A separate source replay checks the SHA-2 and SHAKE builder layouts for all twelve parameter sets using symbolic node bytes, modeled primitives and a drained work queue. The Lean theorem takes the local equations as premises. [Construction theorem](../Cachepath/Construction.lean) · [Builder replay](../../scripts/check-cache-build.py) |
| Layer cache search | Lean proves the shared Rust linear scan terminates and returns the first matching index, or reports a miss exactly when every entry differs. The direct-index shortcut also returns a valid match or correctly reports absence, including with duplicate entries. Fresh Aeneas translations match on Apple AArch64, Linux AArch64 and Linux x86-64. | Eviction, insertion and association of nodes with the signing key remain separate obligations. The runtime key check compares the public seed and root. A full equivalence theorem must account for the relationship between the cache and the secret seed used to build it. [Search theorem](../Cachesearch/Proof.lean) · [Extraction replay](../../scripts/check-cache-path.py) |
| Arm SHA-512 interleaved rounds | The two-round step extracted on Apple and Linux AArch64 matches the proved step. A symbolic schedule checks all 40 steps, both constants per step and independent lanes in one-, two- and four-lane configurations. | Assumes the modeled ARM instructions, valid constant-pool pointer and hardware feature. The surrounding block loaders, accumulation and callers have separate obligations. [Replay](../../scripts/check-arm-sha512-lanes.py) |
| Arm SHA-256 short-block packing | Symbolic execution of optimized AArch64 code checks the 48-byte schedule suffix for arbitrary input digest and address words. It checks all three digest widths, digest load/store round-trip and the memory ranges accessed. | Assumes the AArch64 instruction model, including SIMD subword reversal. The four-round head and callers require separate proofs. [Replay](../../scripts/parallel-proof/arm-pack.py) |
| Apple eight-lane Keccak | For arbitrary input words and round constant, Lean checks all 25 output words of the scalar, SHA3 and NEON round bodies against FIPS 202. A symbolic replay checks the round constants, coordinate ordering, loads and stores for each active lane count from zero through eight. | The replay lifts the Rust bodies under lane-wise intrinsic semantics. The compiler, emitted instructions and CPU feature detection are trusted here. [Replay](../../scripts/check-apple-hybrid.py) |
| Split XMSS and FORS subtrees | For any number of levels and any valid root index, merging the specified consecutive subtrees gives FIPS Algorithm 9 or 15. A Rust replay checks the reducer's child indices, height, hash input order and in-place writes for all supported heights. | The child nodes satisfy their primitive contracts. Absolute indices must fit in the Rust index type. [Theorems](SplitTree.lean) · [Source check](../../scripts/check-split-tree.py) |
| Parallel key generation | Every drained and joined ticket schedule computes the specified XMSS public root. The source check covers the two split policies, the ticket counter, slot writes, parent domain and final reduction. | Assumes normally returning workers, atomic ticket allocation, publication and join semantics. [Key generation theorem](SplitTree.lean) |
| Persistent worker join | Zero outstanding workers implies every published job has finished. The packed completion word preserves the panic bit across worker decrements. | A source check binds publication, borrowing, completion and clearing the job. Five concurrency unit tests (`pool::tests` — covering work-queue + stack scrubbing, nested re-entry, simultaneous caller+worker panic unwinding over borrowed stack buffers, worker panic recovery, and competing dispatchers + parked-worker wakeups) are additionally checked under Miri (`-Zmiri-num-cpus=4 -Zmiri-preemption-rate=0.5`, both Stacked Borrows and Tree Borrows). Still assumes Rust/OS atomic synchronization, condition-variable behavior and thread semantics outside tested schedules. [Join model](Pool.lean) |
| Fused XMSS signature | The eight-lane signer uses the same leaf and sponge calculations as the checked eight-leaf routine. Lean checks selection of the chain value for every possible WOTS digit. A replay checks the authentication-path suffix for every signing index at all four standard XMSS heights. | The three-lane fallback depends on the WOTS signing and recursive node contracts. [Digit selection](FusedWots.lean) · [Source binding](../../scripts/parallel-proof/build.py) |
| Batched verification | In the worker model, per-item results equal the individual verdicts in input order. The short-circuit accumulator returns true exactly when every item verifies. | This theorem models claims, completed checks, rejection and joining. The OS worker pool and individual verification kernels require separate implementation proofs. [Batch theorems](Batch.lean) |
| Parallel WOTS signing | Independent WOTS jobs using the preceding layer's XMSS root produce the FIPS hypertree signature in layer order for every valid parameter set. | The theorem assumes the specified FORS root, authentication nodes and WOTS operations. The signing replay lifts the planner and assembly to symbolic bytes, checks the barrier events and substitutes a worker harness for the persistent pool. [Hypertree theorem](Fused.lean) |
| Active SHAKE batches | Symbolic execution checks every byte of each short-hash, parent-hash and fused FORS leaf permutation input, and all returned lanes. It exercises widths three and eight, active counts from zero to the width and all digest sizes. | Compiles the source with the chosen layout for x86-64 symbolic execution. Permutation outputs are arbitrary, and each active lane must match its own FIPS input. [Replay](../../scripts/parallel-proof/active.py) |
| Metal SHAKE permutation | Lean checks each word of the actual MSL round against the FIPS 202 round for arbitrary inputs and checks the 24 constants. | The source lift uses C++ evaluation of the straight-line array operations and models 64-bit MSL operators as bitvectors. The Metal compiler and device remain trusted. [Replay](../../scripts/check-metal-keccak.py) |
| Metal SHA-256 and SHA-512 compression | A source check binds the round macros, 16-word rolling schedules, rotated working registers, loop bounds and feed-forward. Lean checks constants, rotates, choice and majority functions against FIPS 180-4. | This checks compression on decoded words. Message construction, GPU execution and the composed signer are covered separately below. [Replay](../../scripts/check-metal-sha2.py) |
| Metal GPU pipelines & message construction | Lean proves two-phase vs streaming WOTS+, iterative threadgroup XMSS reduction, two-pass FORS decomposition, disjoint `out_sigs` writes, and composed single/batch keygen and signing across all 12 parameter sets. A C++20 coroutine host replay compiles production `slhdsa.metal` and `slhdsa_shake.metal` under `-Werror -fsanitize=undefined,bounds` checking all 7 ADRS tags, padding, offsets and FFI/zeroize bounds across 24 keygen and 30 sign dispatches. | Trusts the Apple Metal shader compiler and GPU hardware execution beyond the modeled host C++ coroutine semantics. [Pipeline theorems](../Metal/Pipeline.lean) · [Kernel replay](../../scripts/check-metal-kernels.py) |
| HashSLH-DSA framing & digests | For all four pre-hash choices (`SHA-256`, `SHA-512`, `SHAKE128`, `SHAKE256`), fresh 3-target Aeneas extractions prove `format_prehash_message`, `shake128` (FIPS 202 rate-168), `PreHash::hash`, and `hash_slh_{sign,verify}{,_prehashed}` against independent FIPS 205 Algorithms 23 & 25, including context-length and digest-length rejection and completeness. | Assumes the verified `sha256`, `sha512`, `shake256`, `slh_sign_internal` and `slh_verify_internal` contracts. [Spec](../../lean/Spec/PreHash.lean) · [Framing](../Prehash/Proof.lean) · [Digest & Alg 23/25](../Prehash/Digest.lean) · [Framing replay](../../scripts/check-prehash-framing.py) · [Digest replay](../../scripts/check-prehash-digest.py) |
| Cache lifecycle & end-to-end cached signing | Fresh 3-target Aeneas extraction proves `TopTreeCache::{pk_root,matches_key,set_layer_d2_capacity,with_layer_d2_capacity,layer_d2_tree_index,lookup_d2}` and `sha2_ops::sign_from_digest`. Composing with `Cachepath.Construction` and `Cachesearch.Proof`, Lean proves `CacheValid` is preserved across insertion, MRU move-to-front, eviction and precomputation, and that cached signing (layer `d-1` and `d-2` hits) equals FIPS 205 `slhSign` and `hashSlhSign` for all 12 sets. A symbolic Rust replay exercises the full lifecycle across all 12 sets. | Assumes the underlying signing-key association invariant when reusing an existing cache across calls. [End-to-end theorems](../Cachepath/EndToEnd.lean) · [Lifecycle replay](../../scripts/check-cache-endtoend.py) |
| Arm SHA-256 wide kernels & safe callers | Dual-target Aeneas extraction proves `wots_digits_stack`, `base_2b_stack`, `prepare_tlen`, `sort_descending`, and `parent_block_512`. Lean proves the 4-round head (`make_head`) + deferred 60-round body (`finish_from_r4`, `compress_block_lanes`) against FIPS 180-4 and longest-first 4-lane WOTS refill (`sign_fused`, `recover`) against FIPS 205 Algorithms 7 & 8. A symbolic replay checks the production callers across all 6 SHA-2 sets. | Assumes the modeled AArch64 NEON/SHA-256 instructions and CPU feature detection. [Encoders](../Armwide/Encoders.lean) · [WOTS refill](../Armwide/WotsRefill.lean) · [Kernel](../Armwide/Kernel.lean) · [Replay](../../scripts/check-arm-sha256-wide.py) |
| Arm SHA-512 multi-block & parent callers | Lean proves `compress_multi_{1,2,4}` (iterated SHA-512 compression + big-endian truncation), `parents_batch` and `path_parents_batch` (left/right sibling ordering and index halving) against FIPS 205 `T_len` and `H`. A symbolic replay checks `load_block`, NEON `store_trunc`, feed-forward accumulation and all 1/2/4-lane callers. | Assumes the modeled ARMv8.2 SHA-512 instructions and feature detection. [Multi-block & parents](../Paired/Multi.lean) · [Replay](../../scripts/check-arm-sha512-callers.py) |
| Segmented SHAKE, horizontal FORS & refill WOTS | Fresh 3-target Aeneas extraction proves zero-copy segmented SHAKE (`prf_msg_ctx`, `h_msg_ctx`, `shake_{sign,verify}_ctx`, `slh_{sign,verify}`) equals contiguous FIPS 205 Algorithms 22 & 24, and proves `sort_descending`. Lean proves the 8-way horizontal FORS TreeHash stack invariant (`fors_subtree_horiz`, `fors_batch::{sign,recover}`) and longest-first dynamic lane-refill WOTS (`batch::{keygen,sign,recover}`). Hash-consed symbolic oracle replays lift production `fors_batch.rs` and `batch.rs` across all 6 SHAKE sets and widths 3 & 8. | Assumes the verified `shake256::Sponge` and `permute_active` contracts. [Segmented](../Shakeopt/Segmented.lean) · [Horizontal FORS](../Shakeopt/ForsHoriz.lean) · [WOTS refill](../Shakeopt/WotsRefill.lean) · [Segmented replay](../../scripts/check-shake-segmented.py) · [FORS replay](../../scripts/check-shake-fors.py) · [WOTS replay](../../scripts/check-shake-wots-refill.py) |

The remaining trust boundary consists of the persistent pool's unsafe Rust synchronization (`pool.rs`, dynamically audited under 4-CPU Miri Stacked Borrows and Tree Borrows), the Objective-C/Metal compiler and GPU hardware execution, and standard OS/compiler/hardware instruction models. The subtree checks cover tree building at the boundaries described in the [parallel replay](README.md).

Run from the repository root with the proof toolchains installed.

```sh
python3 scripts/check-apple-hybrid.py
python3 scripts/check-metal-keccak.py
python3 scripts/check-metal-sha2.py
python3 scripts/check-metal-kernels.py
uv run --script scripts/parallel-proof/active.py
uv run --script scripts/parallel-proof/arm-pack.py
python3 scripts/check-arm-sha512-lanes.py
python3 scripts/check-arm-sha512-callers.py
python3 scripts/check-arm-sha256-wide.py
python3 scripts/check-shake-segmented.py
python3 scripts/check-shake-fors.py
python3 scripts/check-shake-wots-refill.py
python3 scripts/check-cache-path.py
python3 scripts/check-cache-build.py
python3 scripts/check-cache-endtoend.py
```

Optional Miri UB & data-race audit of the persistent worker pool (`rust/src/pool.rs`):

```sh
cd rust
MIRIFLAGS="-Zmiri-ignore-leaks -Zmiri-num-cpus=4 -Zmiri-preemption-rate=0.5 -Zmiri-seed=0" \
  cargo +nightly miri test --locked --features parallel --lib pool::tests -- --test-threads=1
MIRIFLAGS="-Zmiri-ignore-leaks -Zmiri-num-cpus=4 -Zmiri-preemption-rate=0.5 -Zmiri-tree-borrows -Zmiri-seed=0" \
  cargo +nightly miri test --locked --features parallel --lib pool::tests -- --test-threads=1
```
