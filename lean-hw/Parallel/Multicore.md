# Proof coverage of the persistent worker implementation

| Component | Checked property | Implementation boundary |
|---|---|---|
| Cached XMSS authentication path | Lean checks the extracted cache lookup and append loop, including all output bytes and indices. Given a correctly populated tree and WOTS signature, it produces the FIPS XMSS signature. | Apple AArch64, Linux AArch64 and Linux x86-64 extractions match. Cache construction, key association, replacement policy and complete cached signing still require separate proofs. [Theorem](../Cachepath/Proof.lean) · [Replay](../../scripts/check-cache-path.py) |
| Arm SHA-512 interleaved rounds | The two-round step extracted on Apple and Linux AArch64 matches the proved step. A symbolic schedule checks all 40 steps, both constants per step and independent lanes in one-, two- and four-lane configurations. | Assumes the modeled ARM instructions, valid constant-pool pointer and hardware feature. The surrounding block loaders, accumulation and callers have separate obligations. [Replay](../../scripts/check-arm-sha512-lanes.py) |
| Arm SHA-256 short-block packing | Symbolic execution of optimized AArch64 code checks the 48-byte schedule suffix for arbitrary input digest and address words. It checks all three digest widths, digest load/store round-trip and the memory ranges accessed. | Assumes the AArch64 instruction model, including SIMD subword reversal. The four-round head and callers require separate proofs. [Replay](../../scripts/parallel-proof/arm-pack.py) |
| Apple eight-lane Keccak | For arbitrary input words and round constant, Lean checks all 25 output words of the scalar, SHA3 and NEON round bodies against FIPS 202. A symbolic replay checks the round constants, coordinate ordering, loads and stores for each active lane count from zero through eight. | The replay lifts the Rust bodies under lane-wise intrinsic semantics. The compiler, emitted instructions and CPU feature detection are trusted here. [Replay](../../scripts/check-apple-hybrid.py) |
| Split XMSS and FORS subtrees | For any number of levels and any valid root index, merging the specified consecutive subtrees gives FIPS Algorithm 9 or 15. A Rust replay checks the reducer's child indices, height, hash input order and in-place writes for all supported heights. | The child nodes satisfy their primitive contracts. Absolute indices must fit in the Rust index type. [Theorems](SplitTree.lean) · [Source check](../../scripts/check-split-tree.py) |
| Parallel key generation | Every drained and joined ticket schedule computes the specified XMSS public root. The source check covers the two split policies, the ticket counter, slot writes, parent domain and final reduction. | Assumes normally returning workers, atomic ticket allocation, publication and join semantics. [Key generation theorem](SplitTree.lean) |
| Persistent worker join | Zero outstanding workers implies every published job has finished. The packed completion word preserves the panic bit across worker decrements. | A source check binds publication, borrowing, completion and clearing the job. It assumes Rust atomic synchronization, condition-variable behavior and thread semantics. [Join model](Pool.lean) |
| Fused XMSS signature | The eight-lane signer uses the same leaf and sponge calculations as the checked eight-leaf routine. Lean checks selection of the chain value for every possible WOTS digit. A replay checks the authentication-path suffix for every signing index at all four standard XMSS heights. | The three-lane fallback depends on the WOTS signing and recursive node contracts. [Digit selection](FusedWots.lean) · [Source binding](../../scripts/parallel-proof/build.py) |
| Batched verification | In the worker model, per-item results equal the individual verdicts in input order. The short-circuit accumulator returns true exactly when every item verifies. | This theorem models claims, completed checks, rejection and joining. The OS worker pool and individual verification kernels require separate implementation proofs. [Batch theorems](Batch.lean) |
| Parallel WOTS signing | Independent WOTS jobs using the preceding layer's XMSS root produce the FIPS hypertree signature in layer order for every valid parameter set. | The theorem assumes the specified FORS root, authentication nodes and WOTS operations. The signing replay lifts the planner and assembly to symbolic bytes, checks the barrier events and substitutes a worker harness for the persistent pool. [Hypertree theorem](Fused.lean) |
| Active SHAKE batches | Symbolic execution checks every byte of each short-hash, parent-hash and fused FORS leaf permutation input, and all returned lanes. It exercises widths three and eight, active counts from zero to the width and all digest sizes. | Compiles the source with the chosen layout for x86-64 symbolic execution. Permutation outputs are arbitrary, and each active lane must match its own FIPS input. [Replay](../../scripts/parallel-proof/active.py) |
| Metal SHAKE permutation | Lean checks each word of the actual MSL round against the FIPS 202 round for arbitrary inputs and checks the 24 constants. | The source lift uses C++ evaluation of the straight-line array operations and models 64-bit MSL operators as bitvectors. The Metal compiler and device remain trusted. [Replay](../../scripts/check-metal-keccak.py) |
| Metal SHA-256 and SHA-512 compression | A source check binds the round macros, 16-word rolling schedules, rotated working registers, loop bounds and feed-forward. Lean checks constants, rotates, choice and majority functions against FIPS 180-4. | This checks compression on decoded words. Message construction, GPU execution and the composed signer still require proofs. [Replay](../../scripts/check-metal-sha2.py) |
| HashSLH-DSA framing | For the four pre-hash choices, the formatter rejects invalid lengths and otherwise emits the exact domain byte, one-byte context length, context, DER OID and supplied digest. | Aeneas re-extracts the actual formatter on Apple AArch64, Linux AArch64 and Linux x86-64. Correct computation of the supplied digest and the cached signer are separate obligations. [Theorem](../Prehash/Proof.lean) · [Replay](../../scripts/check-prehash-framing.py) |

The remaining implementation obligations include the persistent pool’s unsafe Rust synchronization, ARM SHA-2 kernels, remaining SHAKE WOTS and FORS kernels, cache lookup and reuse, Metal shaders and Objective-C bridge. The subtree checks cover tree building at the boundaries described in the [parallel replay](README.md).

Run from the repository root with the proof toolchains installed.

```sh
python3 scripts/check-apple-hybrid.py
python3 scripts/check-metal-keccak.py
python3 scripts/check-metal-sha2.py
uv run --script scripts/parallel-proof/active.py
uv run --script scripts/parallel-proof/arm-pack.py
python3 scripts/check-arm-sha512-lanes.py
python3 scripts/check-cache-path.py
python3 scripts/check-split-tree.py
python3 scripts/check-prehash-framing.py
uv run --script scripts/check-parallel-proof.py
```
