# Cached signing and persistent worker proof coverage

## From a signing key to a sequence of public signatures

For all twelve parameter sets, the scalar session theorem starts with the bytes of a well-formed signing key, constructs the top-tree cache, sets its capacity, and runs any finite list of deterministic and randomized public requests. It proves equality to the FIPS 205 result for each request and preserves the cache invariant across hits, misses and evictions. Contexts longer than 255 bytes return an error under the public API model. Requests use the same signing key throughout. SHA-2 messages must fit the modeled address space with room for framing. The proof uses the project's Rust translation, allocation and hash implementation models. [Session theorem](../Cachepath/BuiltSession.lean) · [Public request sequence](../Cachepath/PublicReuse.lean)

The serial `riscv64gc-unknown-none-elf` build with `platform-sha2` selects the portable SHA-2 and scalar SHAKE paths. Fresh extraction checks bind its cfg-selected SHAKE builder and signer to the scalar definitions. For SHA-2, source-bound platform replays now take three seed blocks through serial cache construction, optional eager warming, public cached signing, and successful verification by the corresponding platform verifier. They cover Linux x86-64 and the wide-disabled Apple and Linux AArch64 branches. [Platform round trips](../Cachepath/PlatformSha2RoundTripLinux.lean) On a hosted parallel build, the constructor theorem covers both successful leaf filling and fallback after a failed attempt, conditional on the worker's leaf-fill contract. The parallel signing scheduler and optimized hash kernels have the separate checks below. The `keygen_with_cache` entry can also initialize the session directly from three seed blocks. Its proof relates every public and private key byte and the returned cache to the same FIPS keypair. The round-trip theorem signs with that cache and calls the portable verifier with the generated public key. [Generated-key session](../Cachepath/KeygenSession.lean) · [Round-trip theorem](../Cachepath/KeygenVerify.lean) · [Combined portable implementation](../Cachepath/PlatformPortable.lean). [Portable builder](../Cachepath/BuilderPortable.lean) · [Portable signer](../Cachepath/PortableSigner.lean) · [Platform replay](../../scripts/check-cache-sha2-platforms.py) · [Parallel builder](../Cachepath/BuilderParallel.lean)

To repeat the eight Miri runs for the persistent worker pool, use four simulated CPUs and run the tests concurrently. Leak detection is disabled for the process-lifetime pool and the secondary panic payload retained when a destructor itself panics.

```sh
cd rust
for model in "" "-Zmiri-tree-borrows"; do
  for seed in 0 1 2 3; do
    MIRIFLAGS="-Zmiri-ignore-leaks -Zmiri-num-cpus=4 -Zmiri-preemption-rate=0.5 -Zmiri-seed=$seed $model" \
      cargo +nightly-2026-09-17 miri test --locked --features parallel --lib pool::tests -- --test-threads=6 || exit 1
  done
done
```
