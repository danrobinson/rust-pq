# Metal signature values

[CommandValues.lean](CommandValues.lean) composes the command epochs, typed signature layout and FIPS 205 pipeline model. For supported parameters, well-formed signing keys and a successful public signing batch, the result contains the FIPS signature of each request in order, with its context and supplied randomness. The theorem covers pooled buffers larger than the current output, an empty batch and context rejection. The host checker instantiates it for both XMSS modes on all twelve parameter sets. [Host traces and public wrappers](../../scripts/metal-command.py) · [FIPS pipeline model](Pipeline.lean)

The theorem takes a local value contract for each command. Its premise says that if every region read by that command contains its intended values, the command produces the intended values in its own output regions. Host initialization has no inputs in the command graph. Each GPU input has exactly one writer in an earlier epoch. Induction on epochs then supplies the local premises without assuming that the returned buffer already contains a valid signature.

| Producer | Value checked |
|---|---|
| Host | Context guard and framing, argument order to the randomizer and digest routines, key packing, selected key, descriptor fields and offsets, randomizer prefix and returned slices. The host checks bind the Rust statements and rely on the CPU primitive contracts. |
| WOTS chain tips, two-phase and streaming XMSS leaves | WOTS PRF and hash address at each step, chaining value, ordered chain tips, address encoding, all compression or permutation inputs, padding, output truncation and word order. |
| FORS passes and XMSS reduction | The leaf secret and its PRF/F domain, ordered children, absolute node index and height at every parent hash, sibling node values, subroot publication, final root and output serialization. |
| FORS public key | Ordered tree roots, full hash transcript and truncated result. |
| WOTS signature | Selected FORS root or preceding layer root, message and checksum digits, chain length, key and address, final serialized bytes. |

The [shader value checker](../../scripts/check-metal-values.py) uses production MSL function bodies and CBMC bitvectors. Key data, messages, target indices, descriptor fields and cryptographic outputs are symbolic. Hash comparisons check the bytes entering compression or permutation and allow arbitrary results, so the claims compose with the primitive implementations. At threadgroup barriers the checker supplies an arbitrary table of node words indexed by height, absolute node index and word number. Each producer must write the specified entry. The prior [barrier checker](../../scripts/check-metal-workgroups.py) establishes that all lanes have published the required entries before the next phase reads. The [address checker](../../scripts/check-metal-reads.py) and grid checks justify specializing active lanes to their row-major coordinates and rebasing accesses to the selected records.

For two-phase signing, Lean now derives the chain-tip command's local contract on every parameter set. The source checker translates the four dispatch index expressions and step count from each production kernel and checks the entire key-loading, short-hash loop and word-store bodies. Lean proves that, starting with arbitrary pool contents, every interleaving of the dispatched word stores produces the expected chain tips. Twelve additional public signing theorems use this result and require local value contracts for the remaining commands. A changed chain-index operator and a broadcast of the first word are mutation controls for each family. [Executable chain dispatch and proof](ChainDispatch.lean)

Lean also derives the XMSS leaf producer’s contract for both modes on all twelve parameter sets. In two-phase mode, the compression pass reads the word buffer produced by the chain dispatch. The proof reassembles each chain and checks the sequence of SHA-256 words, SHA-512 word pairs or SHAKE lanes absorbed. In streaming mode, it constructs the same transcript directly from the chain loop. The 24 public theorem instances accept arbitrary store order and initial leaf-buffer contents. Mutating an output word or duplicating a stream input fails the source projection for each of the four kernel bodies. [Leaf dispatch and buffer composition](LeafDispatch.lean) · [Production shader projection](../../scripts/metal-proof/leaf_dispatch.py)

For both modes, the signature pool in the strongest public theorem is computed by the final WOTS command’s scattered byte stores over an arbitrary initial buffer. Lean proves that every WOTS address has a unique writer and that its byte matches the corresponding FIPS signature at the same batch, layer, chain and byte index. It checks the first-layer FORS key or preceding-layer XMSS root, the high and low nibbles, the three checksum digits, chain steps, and the SHA-2 big-endian or SHAKE little-endian output stores. The proof accepts every permutation of the submitted grid. Input records and roots remain obligations of their producers. [WOTS output proof](WotsOutput.lean) · [Shader projection](../../scripts/metal-proof/wots_output.py)

The FORS public-key command uses the same stream and word-buffer proofs. Lean reads its ordered tree roots from the pass-one buffer when the tree has one pass, or from the pass-two buffer when the tree is split. It proves that the resulting T hash is the FIPS FORS public key and that the WOTS kernel reads it from the actual published buffer. This contract is discharged in all 24 public instances. [FORS public-key proof](ForsPkDispatch.lean) · [Shader projection](../../scripts/metal-proof/fors_pk.py)

The modeled host initializer derives its key table, indices and descriptor values from the framed requests. Lean proves the first matching slot remains valid after subsequent unique keys are appended, including repeated-key batches. It replays the randomizer prefix copy into arbitrary pool contents and proves that subsequent non-randomizer stores and the final WOTS scatter preserve those bytes. The strongest public statement accepts intermediate FORS and XMSS signature writes at their typed layout locations. [Host values and randomizer preservation](HostValues.lean)

XMSS reduction reads the physical leaf-word buffer produced by the selected leaf kernel. The source projection distinguishes initial leaf reads from threadgroup reads after a barrier and preserves child ordering, address height and node index. Lean proves each active node, traces the root through its word buffer into WOTS signing, and traces each authentication byte through all later writes into the FIPS signature. [XMSS reducer](XmssDispatch.lean) · [Signature fields and scatter preservation](ReducerBytes.lean) · [Both shader projections](../../scripts/metal-proof/xmss_reducer.py)

The chain-tip, leaf, FORS public-key and WOTS proofs use the specification PRF, F and T at the hash boundaries, with native words represented by their canonical serialized bytes. The separate shader and primitive checkers support this interpretation, including the precompressed SHA-2 seed state. The public theorem assumes that Metal executes the submitted grid and presents coherent buffers. The two FORS reduction passes retain local execution contracts supported by the shader, host and address checkers. Application to a device assumes the MSL and host projections describe the compiled program, the Objective-C runtime and the device. The contracts cover integer and pointer semantics, coherent buffers, barriers, valid buffer bindings, CPU and GPU primitives and successful completion. Full native signature comparisons use finite test vectors.

Run from the repository root with CBMC installed or `CBMC` set to its executable.

```sh
python3 scripts/check-metal-kernels.py
python3 scripts/check-metal-values.py
uv run --script scripts/check-metal-reads.py
uv run --script scripts/check-metal-workgroups.py
```
