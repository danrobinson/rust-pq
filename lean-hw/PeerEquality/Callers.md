# RustCrypto SLH callers

Run `scripts/check-peer-callers.sh` from the repository root. It checks the pinned crate archive against the benchmark lockfile, regenerates the signing and verification call graphs, compares them to the checked-in Lean code and audits the kernel axioms.

`keygen_fips`, `sign_fips` and `verify_fips` characterize the packed secret/public key pair, serialized signature and acceptance Boolean. `ht_fips` proves the peer’s initial layer and its remaining loop yield Algorithm 12. The last iteration omits the unused recovery call. The domain includes all twelve standard parameter sets. `sign_context` and `verify_context` handle arbitrary multipart messages, the context length byte, and rejection above 255 bytes. `sign_entry_wrong_randomness` covers the hidden peer API's invalid randomizer size and `sign_entry_rejects` checks that context rejection takes precedence.

The call graph is a restricted source translation. It preserves Rust let bindings, selectors, calls, arguments and returns. The checker also recognizes the exact bodies of the public wrappers, seed constructor and hypertree loop. The concrete tree/leaf split, big-endian reads, 64-bit wrapping mask, and all source suite dimensions are checked by `split_correct` and the extractor. It trusts its Rust-to-Lean interpretation of initialized byte arrays, options, loops, views and typed object construction. Seeded hash contexts store the public seed; typed child signatures are observed through their byte encoding. Raw verification receives a parsed signature with the standard lengths. RNG observations concern the returned bytes and error status. No distribution assumption is used.

`ChildLaws` lists the independent cryptographic obligations for three WOTS operations, the binary hash, the message hashes and FORS. The caller theorems are conditional on those child behaviors. The caller uses the source-bound `htVerifyWith` directly. Its proof reduces hypertree verification to the same XMSS recovery contract used by signing. `sha2_prf` and `sha2_hmsg` discharge the two message-hash obligations for the checked SHA-2 provider routes. The underlying source, hardware and compiler boundaries are documented in `RcSlhSha2/README.md`.

The twelve theorems ending in `_facades` compose these caller refinements with the actual Aeneas-translated library entry points. For matched input bytes, random draws, and valid randomizer sizes, they prove identical generated keys and signed bytes, and identical verification success or failure. They inherit the local façade’s allocation headroom condition. `round_trip` proves that keys with the required seed lengths produce signatures accepted by the peer caller. `all_slots` proves that every preallocated layer is filled and unwrapped in order for arbitrary XMSS outputs.

The three XMSS algorithms in `PeerEquality.Xmss` use the typed WOTS hash address and serialized signature row interpretations. The locked-source gate recognizes all three Rust method bodies and the address conversion. Given WOTS key generation, signing and recovery and the binary hash H, `PeerXmss.operations_fips` proves the complete recursive node, serialized signature, and recovery result agree with FIPS. The sign proof follows the successively shifted leaf index. Recovery proves the parent index and the left/right order at every level for arbitrary authentication bytes. The finite machine index bounds, typed address representation and row encodings are checked separately by the XMSS Kani and signature encoding gates.

The public comparison instantiates all three source-bound XMSS algorithms via `PeerXmss.operations`. `ChildLaws.xmss` derives their correctness from WOTS public keys, signing, recovery and the binary hash.
