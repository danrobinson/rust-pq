# Linked Apple internal SHA-2 signing

Lean replays all six public SHA-2 `slh_sign_internal` entries from the Apple arm64 ACVP executable with SHA-256 `ab672dc82d293ec220beb29f475bedda4614d59c76636cd16edef18705e1ac0a`. Each replay constructs a `LinkedArm.Signer.Sha2.Signature` for the output identified in returned memory. The corresponding equality theorem identifies those bytes with `Spec.slhSignInternal` when the invoked callees satisfy their local contracts. [SHA-2 trace construction](../lean/Spec/ArmSha2InternalSigner.lean) · [Measured witnesses](../lean/Spec/AppleSha2InternalSignerWitness.lean)

The driver checks the PRF key block, supplied randomness, original message slice, and the randomizer returned by the PRF. It checks that H_msg consumes that randomizer with the public seed, public root and original message. Its local hash contract describes the HMAC inner and outer hashes, the first message hash, and every MGF1 counter. The machine digest parser checks the exact byte loads and coordinate masks. On the 192- and 256-bit entries it also checks the paired native address-field store interleaved with that computation.

SHA-2 FORS signing and recovery both receive the beginning of the same live digest allocation, its exact prefix length, the full seeded hash context, and the checked FORS address. Their local contracts include base-2^a conversion. The hypertree receives the recovered root, secret seed, hash context and both observed digest coordinates. The replay checks the order, source pointer, destination pointer and size of each copy used to return the signature, plus the final vector metadata, allocation ownership and restored registers.

* For SHA-2-192 and SHA-2-256, the seed-context callee is contracted at its linked address. The driver checks its public-seed input, disjoint output slot, and transfer of the entire context to each consumer.
* For SHA-2-128, the seed compression contract covers 42 exact machine words at the signer's linked address. Lean binds the contract to the seed vector, zero loop counter, both halves of the SHA-256 IV and all 64 round constants. Surrounding instructions assemble the zero prefix, digest words and seed in memory. The independent SMT driver checks the inlined round circuit against its Arm hash-instruction model.

There are four representative successful allocator policies per parameter set and seven rejected mutations covering the PRF key, digest assembly, seed compression instruction, tree register, returned length, paired address store and external seed-context input. `lake build Spec.AppleSha2InternalSignerWitness` replays the checked-in certificates. The binary gate regenerates them from the executable with `scripts/apple-binary/check.py`. [Generator](../scripts/apple-binary/signer_witness.py) · [Independent native SMT driver](../scripts/linked-signer/driver.py)

The result assumes the local HMAC/H_msg, seeded hash, FORS and hypertree equations, successful runtime operations, and the restricted instruction and memory model. The replay covers fixed disjoint addresses and the specified allocation policies. Other binaries, all possible physical address placements and the public context-framing paths require separate proofs.
