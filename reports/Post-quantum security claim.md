# What the SLH-DSA security proofs establish

**Claim for the library.** For all twelve pure SLH-DSA parameter sets, Lean proves a concrete reduction from quantum chosen-message forgery against the modeled byte API to twelve games on its fixed hash functions. An adversary that forges with probability p yields a primitive-game adversary with advantage at least p/27. Separate theorems give numerical forgery bounds at specified resource budgets for idealized hash functions. The evidence reviewed here leaves the full FIPS category claim open. [Fixed-function theorem](../quantum/Integration/SlhDsaFixedPrimitiveWitness.lean) · [Numerical results by model](../quantum/STATUS.md)

## The experiment and the benchmark

In the FIPS §11 experiment an attacker gets an honestly generated public key and can request signatures on up to 2⁶⁴ adaptively chosen messages under that key. It succeeds by producing a valid signature on a message it never submitted. NIST evaluates quantum attackers with classical access to the signer. Lean implements this freshness test and also studies strong unforgeability, in which a fresh valid signature on a previously signed message can count. These experiments concern mathematical signing and verification. Extending their conclusions to an executable requires the corresponding implementation and leakage assumptions. [FIPS 205, §11](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.205.pdf) · [NIST evaluation criteria, §§4.A.4–5](https://csrc.nist.gov/projects/post-quantum-cryptography/post-quantum-cryptography-standardization/evaluation-criteria/security-%28evaluation-criteria%29) · [Lean experiments](../quantum/PQ/Interactive/EUFCMA.lean)

A precise comparison fixes a success probability, a computation model and a budget for signing requests. For example, at success ½, compare the minimum adversarial work to forge with the minimum work to recover a random block-cipher key at the same success and allowed depth. NIST categories 1, 3 and 5 use the 128-, 192- and 256-bit key-search benchmarks. NIST allows multiple realistic cost metrics and explicitly made a security proof optional in its submission criteria. A logical-gate count at fixed depth would address one metric. A bound on the number of calls to an ideal function answers a different quantitative question. [NIST evaluation criteria](https://csrc.nist.gov/projects/post-quantum-cryptography/post-quantum-cryptography-standardization/evaluation-criteria/security-%28evaluation-criteria%29)

## Reproducing the parameter argument

The SPHINCS+ v3.1 submission, reference 10 in FIPS 205, gives a generic work estimate in §7.1.1. Let n be the node size in bytes. Its coefficient is α = 2⁻⁽⁸ⁿ⁾ + P, where P is the probability that prior independent uniform digests cover the FORS choices in a fresh digest. The submission uses −log₂ α as a classical score and half that score as a quantum estimate, suppressing constants. Lean now connects the exact decoded-digest event to the submission’s binomial sum and certifies the following intervals for up to 2⁶⁴ independent targets. [Submission, §7.1.1, Table 3 and Appendix A](https://sphincs.org/data/sphincs+-r3.1-specification.pdf) · [Checked coefficient](../quantum/Integration/SlhDsaSubmissionEstimate.lean)

| Set | Submission Table 3 “bitsec” | Certified interval for α × 2⁸ⁿ |
|---|---:|---:|
| 128s | 133 | [1, 33/32] |
| 128f | 128 | [1, 2] |
| 192s | 193 | [1, 3/2] |
| 192f | 194 | [1, 5/4] |
| 256s | 255 | [1, 3] |
| 256f | 255 | [1, 3], sharpened to (2, 3] at 2⁶⁴ targets |

Two conclusions follow. First, the simplified generic estimate tracks the node width to within log₂ 3 bits classically, or half that difference on its quantum scale. Second, the 133, 193 and 194 entries cannot be values of the stated combined score, even rounded to the nearest integer. The uniform-guess term alone caps the score at 128 or 192 respectively. For 128s the checked interval puts the score between roughly 127.96 and 128. FIPS Table 2 assigns **category 1** to that set. The numerical inconsistency concerns the submission’s “bitsec” column. No forgery follows from it. The definition of P assumes independent targets. A proof about signing additionally has to account for adaptive message choice and the signer’s interaction with the same hash function the adversary can evaluate. [FIPS Table 2](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.205.pdf) · [Adaptive signature theorem](../quantum/Integration/SlhDsaShakeAdaptiveSignature.lean)

## What the literature adds

- **The designers’ original argument and its repair.** The submission flags an error in its earlier WOTS reduction. Hülsing and Kudinov give a repaired multi-instance argument and quantum query bounds for generic attacks on hash properties. Barbosa and coauthors subsequently machine-checked a modular SPHINCS+ proof in EasyCrypt. The Lean fixed-function theorem agrees with the reduction strategy and identifies the actual primitive adversaries. A term-by-term identification of every resource charge with those papers remains unverified. [Repaired proof](https://eprint.iacr.org/2022/346) · [EasyCrypt paper and artifact](https://github.com/MM45/FV-SPHINCSPLUS-EC)
- **A recent comparison puts the gap in perspective.** Do and coauthors’ 2026 preprint replaces one multi-target assumption by a bound that tracks revealed targets. For 256s their Table 4 reports quantum work exponents of 127 for the tight estimate, 82 for the loose estimate and 91 for their refinement. These are the authors’ evaluations in their query analysis. They illustrate how far two analyses of the same scheme can differ without exhibiting different attacks. Comparing 91 with this repository’s SHAKE-256s threshold would additionally require aligning the games, constants, success thresholds and resource units. [Preprint, Table 4 and discussion](https://eprint.iacr.org/2026/632)
- **Cryptanalysis can change the standard.** A published classical forgery result lowered the estimated strength of earlier category-five SPHINCS+ instances using SHA-256. FIPS Appendix A records the change to SHA-512 for several functions in the higher SHA2 categories. The earlier result alone cannot determine the strength of the final instantiation. This is an example of the kind of evidence that warrants revisiting a category. [Published cryptanalysis](https://www.nist.gov/publications/breaking-category-five-sphincs-sha-256) · [FIPS 205, §11.2.2 and Appendix A](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.205.pdf)

## What would settle a stronger claim?

The weighted reduction proves that success in the fixed-function signature game forces success in a named hash game. To use it for a cost threshold, the hash-game advantage bounds must hold for the **constructed machines**, including their signing-simulation overhead. The public-query model admits arbitrary deterministic computation on the public input at zero query cost. Lean proves that any work measure bounded by this cost assigns zero work to all such computations. This is a formal reason that tuning the numerical coefficients alone cannot settle the category comparison. [Fixed-function reduction](../quantum/Integration/SlhDsaFixedPrimitiveWitness.lean) · [Cost-model theorem](../quantum/Integration/SlhDsaPathCostScope.lean)

A sufficient positive result for a chosen model would combine a signature-work lower bound with a reference key-recovery algorithm of no greater cost at matched success. Alternatively, a resource-preserving reduction from reference key recovery to forgery could establish the ordering directly. Two separate lower bounds, one for each problem, do not order their actual minimum costs. The checked ideal-cipher lower bound is valuable as a reference in its own oracle model. For a negative result one would need evidence of a cheaper successful forgery against the **final** parameter set under comparable resources. An upper bound that reaches one only establishes that the proof stopped giving information. The assessment found neither an end-to-end category proof nor a counterexample against the final standard.
