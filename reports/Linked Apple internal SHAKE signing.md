# Linked Apple internal SHAKE signing

For the Apple arm64 ACVP executable with SHA-256 `ab672dc82d293ec220beb29f475bedda4614d59c76636cd16edef18705e1ac0a`, Lean replays the six public `slh_sign_internal` entries, including their three shared internal driver implementations. Given the results of the cryptographic callees on the arguments observed by the replay, it constructs a `LinkedArm.Signer.Signature` trace for the bytes selected by the returned vector. The existing `supported_internal_eq` theorem then identifies these bytes with `Spec.slhSignInternal`. The core replay uses the whole linked driver and follows machine-computed PCs. [Instruction replay and trace constructor](../lean/Spec/ArmInternalSigner.lean) · [Artifact witnesses](../lean/Spec/AppleInternalSignerWitness.lean)

* The replay checks the parameter-record bytes, secret-key slices, the initial zeroed sponge, three ordered absorb calls, and the copied sponge passed to finish. Both consumers of the message must receive the original pointer and the same opaque length. The local absorb and finish equations imply the randomizer equation in the signature trace.
* The digest parser executes the native bounds comparisons, byte loads, accumulator loops and bit masks on symbolic byte offsets. Lean proves that interpreting the resulting bit projections gives the specified tree and leaf indices for arbitrary digest bytes of the correct length. The rest of the driver checks both digit conversions, the seven address fields, the FORS arguments and signature pointer, and the hypertree call including its message, indices and seeds. [Coordinate semantics and interpretation](../lean/Spec/ArmSignCoordinates.lean)
* The driver executes the native Rust vector assembly, records live allocations and deallocations, checks each copy's provenance, destination and size, and reads the final capacity, length and pointer from the ABI return slot. It checks every stored randomizer cell and the order and extent of the two copied byte ranges. Their contents are supplied by the particular FORS and hypertree calls that produced them. Five mutation proofs cover the secret-key offset, digest assembly, address type, tree register and final vector length.

The Lean execution uses fixed disjoint addresses, exact-capacity intermediate vectors and four representative successful reserve policies. These exercise the four combinations of growth branches for the returned signature. The separate native SMT driver checks symbolic capacities. The Lean result needs the runtime contracts for allocation, deallocation and memory copy. It also needs local equations for sponge absorption and finalization, H_msg, both base conversions, FORS signing and recovery, and the hypertree's XMSS layer calls. The complete callee bodies have separate proofs and native checks. Connecting them all to this replay in one formal ISA semantics remains open. The public framing and external APIs, allocation failures, arbitrary physical address placements and other binaries are outside this theorem. [Native SMT driver](../scripts/linked-signer/driver.py)

Run `lake build Spec.AppleInternalSignerWitness` from `lean/` to replay the checked-in words and mutation proofs. Running `scripts/apple-binary/check.py` on the executable re-extracts its function bodies, immutable parameter rows, local callee addresses and imported memcpy stub, then checks the freshly generated witness.
