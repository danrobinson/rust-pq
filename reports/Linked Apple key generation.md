# Linked Apple key generation

For the Apple arm64 executable with SHA-256 `ab672dc82d293ec220beb29f475bedda4614d59c76636cd16edef18705e1ac0a`, Lean replays both public key-generation ABIs for the twelve FIPS 205 parameter sets. The kernel checks the linked instructions along each successful path. Each replay returns the entire secret key and public key from modeled final memory. The proof interprets these symbolic memory cells for arbitrary four-byte groups of input and subtree-root bytes. Given the specified XMSS subtree result, it constructs a `LinkedArm.Signer.KeyGeneration` trace. Its `eq_spec` theorem identifies both returned keys with `Spec.slhKeygenInternal`. [Instruction semantics and trace constructor](../lean/Spec/ArmKeygen.lean) · [Linked instruction and parameter witnesses](../lean/Spec/AppleKeygenWitness.lean)

The `keygen` ABI takes one buffer of three seeds and separate output buffers. The `slh_keygen_internal` ABI takes three seed pointers and returns a contiguous pair of keys through its indirect return pointer. The replay checks every reached branch and return, exact parameter bytes, the active stack bounds, writes to the returned keys, the restored stack pointer, and preserved register cells. At the XMSS call it checks the secret seed, zero index, subtree height, public seed or seed context, all seven address fields, and a disjoint output buffer.

| Family | Scope of the Lean replay |
|---|---|
| SHAKE | The subtree receives the original public seed. Its result is the only cryptographic call contract. |
| SHA-2 192 and 256 | A second contract covers the linked seed-context function. The replay checks its seed input, disjoint output slot, and transfer of its complete output to the subtree. |
| SHA-2 128 | The seed compression loop is inlined. Lean binds its contract to 42 exact words, its linked address, SHA-256 initial values in the observed vector order, and all 64 round constants. It checks the starting counter and seed vector. Outside this region it executes the context assembly and checks the zero prefix, eight digest words, and public seed. A separate native symbolic check follows the loop and compares its circuit against the hardware SHA model. [Seed compression checker](../scripts/linked-signer/sha256_seed.py) |

Seven checked controls cover a wrong XMSS layer, wrong result destination, incorrect register restore, changed parameter height, wrong SHA-2 seed input, changed compression opcode, and a changed SHA-256 round constant. Rebuild with `lake build Spec.AppleKeygenWitness` from `lean/`. Running `scripts/apple-binary/check.py` on the executable regenerates the proofs from the image and checks them in Lean. [Artifact reader and witness generator](../scripts/apple-binary/keygen_witness.py)

The model uses fixed disjoint call-frame, input, and output regions, a restricted little-endian AArch64 decoder, and successful fixed-size calls. The proof assumes that the decoder models these instructions correctly, that the loader supplies the measured code and constants, and that the contracted callees obey their memory and register contracts. It does not establish a refinement for arbitrary physical addresses or the complete ISA. The SHA-2 seed routines and XMSS implementations have separate machine-level checks. A unified Lean proof connecting those instruction executions to each call contract remains open.
